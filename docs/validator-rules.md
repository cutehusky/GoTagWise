# Complete validator and Gin binding rule inventory

The same 166 catalog rules are handled in `validate` and Gin `binding`. Both have rule-level hover/Quick Documentation, completion, parameter checks and datatype filtering. Built-in names can be overridden with the custom-rule allowlist.

A displayed `=parameter` normally requires a nonempty parameter. `unique` and `validateFn` also work without a parameter. Supported `time.Time` ordering rules (`gt`, `gte`, `lt`, `lte`, `min`, `max`) can omit it. Most pointer fields are dereferenced before rule checks. Unknown/interfaces/custom runtime conversions stay conservative.

Datatypes below describe the plugin's static compatibility policy. String/numeric format rules are recognized; the plugin does not validate actual application input, run filesystem/network checks or execute custom validation functions.

## Syntax and reference behavior

Commas combine rules; `|` supplies alternatives. `dive` moves to collection elements/map values, `keys` switches to map keys and `endkeys` restores values. Nested collection traversal is tracked. Single quotes preserve spaces in parameter values.

Reference paths use Go field names, including nested/indexed/promoted fields, rather than JSON/form aliases. Scalar comparison kinds must match (for example, int and int64 differ). Same-kind collection comparisons use lengths. Presence rules allow unrelated field types. Conditional literals are checked against the referenced field, not the field carrying the condition. See [reference examples and limitations](validator-references.md).

The reference parser also recognizes the Field Value shape of `skip_unless`, but that name is **not** in this completion/catalog vocabulary and is reported unknown by default. Runtime validator rules not listed above must be configured as custom or used with unknown-rule diagnostics disabled. Custom overrides bypass built-in datatype/reference assumptions.
